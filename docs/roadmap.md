# 🗺️ 路线图

> MCPCat 平台的演进方向

## 📌 总体策略

MCPCat 的核心定位是 **MCP 能力聚合网关**。

我们不会把自己限制在"数据 API 超市"——这只是切入点。MCPCat 将沿着**五层能力**逐步扩展，最终成为 AI Agent 的**基础设施**。

---

## 🧬 五层能力模型

```
数据查询类（当前）  →  动作执行类  →  SaaS 集成类  →  AI 能力类  →  私有自动化类
  切入点            建壁垒         做留存         高毛利         深护城河
```

| 层 | 类别 | 典型工具 | 商业角色 | 状态 |
|----|------|---------|---------|------|
| **L1** | 数据查询 | 天气、快递、股票、IP | 切入点：好定价、好统一格式、风险低 | ✅ 当前 |
| **L2** | 动作执行 | 发邮件、发短信、建日程、下单 | 壁垒 + 高客单 | 🟡 规划中 |
| **L3** | SaaS 集成 | Notion、飞书、GitHub、企微 | 留存：接进去就不想走 | ⚪ 远期 |
| **L4** | AI 能力 | 文生图、TTS、OCR、向量检索 | 高毛利现金流 | ⚪ 远期 |
| **L5** | 私有自动化 | 浏览器自动化、RPA、代码沙箱 | 深护城河 | ⚪ 长期 |

> **数据类只是切入点，不是终局。** 但数据类验证了产品形态和计费链路，是后续四层的基础。

## 💰 商业模式演进

### 阶段 1：流量验证（v0.x - v1.0）

- 目标：验证产品形态 + 计费链路
- 模式：免费 + 按次付费
- 关键指标：DAU、调用量、付费转化

### 阶段 2：客单价提升（v1.5 - v2.0）

- 目标：提升 ARPU
- 模式：分层定价 + 工具包
- 关键指标：ARPU、续费率、工具使用广度

### 阶段 3：订阅化（v2.0+）

- 目标：稳定收入
- 模式：会员订阅 + 企业套餐
- 关键指标：MRR、Churn、LTV

### 阶段 4：生态化（v3.0+）

- 目标：平台化
- 模式：开发者市场 + 私有部署
- 关键指标：第三方 Adapter 数、生态 GMV

## 🛡️ 合规与商业风险

### 当前定性

**MCPCat 卖的是「MCP 接入与集成服务」，不是转售 API 数据。**

数据调取只是交付这个服务时用到的基础设施。

### 剩余风险

| 风险 | 性质 | 当前对策 |
|------|------|---------|
| 上游异常流量风控 | 商业合同 | 流量分散 + 多供应商冗余 |
| 服务层被认定过薄 | 定性 | 每个 Adapter 有实质封装价值 |
| 供应商条款收紧 | 外部 | 保留切换 / 自建数据源能力 |

### 备选合规路径（规模化后）

1. **正规分销**：阿里云云市场授权分销商
2. **自建/自产数据源**：天气、汇率、快递、IP 归属等
3. **用户自带 key**：MCPCat 纯收服务费
4. **聚合开源/可商用源**：专挑明示可商用的 API
